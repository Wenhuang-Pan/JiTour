## Implementation Steps

1. **版本号**：`pubspec.yaml` → `2.3.0+6`；`UpdateService.currentVersion` → `2.3.0`（关于页副标题动态跟随，无需另改）。
2. **自动记账余额联动**：在 `PendingTransactionService.confirm` 中，交易落库且 pending 状态更新成功后，用 `AccountService.getAccountByName(account)` 解析账户，`currentBalance -= effectiveAmount`（该路径固定为支出）并 `updateAccount` 保存。账户不存在时 `debugPrint` 告警但不阻断（交易已创建，避免数据回滚复杂度）。
3. **定期交易余额联动**：在 `executeRecurringTransaction` 落库后，按 `recurringTransaction.isIncome` 对 `getAccountByName(account)` 做加/减并保存；账户缺失同样仅告警。
4. **历史余额一次性迁移**（新增 `BalanceMigrationService.runIfNeeded`）：
   - 幂等标志：`DatabaseService.autoAccountingPrefs` 写入 `balance_migration_v230_done = true`，执行过则直接返回。
   - 遍历 pendingTransactions box 中 `status == confirmed` 的记录；其 `confirmedTransactionId` 对应交易存在且未删除（`deletedAt == null`）时，按交易 `account` 名称解析账户并 `currentBalance -= transaction.amount`。
   - 按账户聚合后一次性保存，减少 IO；账户缺失/交易缺失分别计数并 `debugPrint`。
   - 全程 try-catch，失败不写完成标志、不阻断启动。
   - WHY: 仅追溯自动记账路径（pending 表有精确关联 ID），定期交易历史无来源字段无法安全区分；转账不产生流水故不受影响。
5. **接入迁移**：`main.dart` 在 `DatabaseService.init()` 之后、`checkAndExecute()` 之前 `await BalanceMigrationService.runIfNeeded()`。
6. **搜索关键词增强**（`FilterService.filterTransactions`）：
   - 方法入口预构建 `tagId → tagName` 映射（遍历一次 `TagService` 全部标签，O(标签数)），避免在交易循环内重复查 box。
   - 关键词命中条件新增：`locationName` 包含、交易 `tagIds` 对应任一标签名包含。
   - 修正既有标签筛选 bug：基于 `t.tagIds`（ID 列表）判断，兼容传入值为标签 ID 或标签名称。
7. **首页搜索体验**：
   - `transactions.isEmpty` 时区分：`_filterConditions.hasFilters` 为真 → 新空状态"未找到相关账单/试试更换关键词或清除筛选条件"+ "清除筛选"按钮（复用 `_clearFilters`）；否则保持原空状态。
   - `hasFilters` 为真时隐藏月度预算卡片（`_buildMonthlyBudgetCard`）与定期提醒（`_buildRecurringTransactionReminder`）两个 sliver，保留筛选指示器与搜索框，结果列表上移。
8. **校验**：`dart analyze` 改动文件 0 error；`flutter analyze` 全量确认无新增告警。
9. **真机/模拟器验证清单**（系统 PowerShell 运行）：
   - 自动记账：悬浮窗/待确认页 confirm 一笔后账户余额立即减少；改金额 confirm 按修改后金额扣减。
   - 定期交易：立即执行一笔收入/支出后余额对应增减；同日重复执行拦截不产生二次扣减。
   - 迁移：升级安装后启动日志出现一次性补扣汇总；二次启动不再执行；账户余额数值正确。
   - 搜索：标签名、位置可搜到；无结果显示新空状态；清除筛选恢复；筛选态顶部卡片隐藏。

## Dependencies and Considerations

- 无 Hive 模型/TypeId 变更，**零数据迁移风险**；余额迁移仅调整 Account.currentBalance 数值，幂等且只执行一次。
- 迁移依赖 pending 表与正式交易的关联完整性，已对"交易被删除/账户缺失"做跳过处理。
- `FilterService` 引入对 `TagService` 的同层依赖，无循环依赖（TagService 不依赖 FilterService）。
- 账户名被用户改名后，历史交易中的旧名称无法解析到账户（与手工记账现有行为一致），迁移与联动均做跳过+日志处理。
- 定期交易的历史执行记录不补扣（用户已知情），用户可在账户编辑页手动调整余额。

## Risks

- **补扣导致余额变为负数**：用户若曾手动把账户余额调低过，自动补扣可能叠加。缓解：迁移仅执行一次、日志输出每账户变动金额；账户页支持手动改余额，必要时可自行修正。
- **迁移与启动时定期交易执行的先后**：已安排先迁移后 `checkAndExecute`，定期交易新逻辑扣减不会被重复迁移（迁移只处理 pending 表，不碰 recurring）。
- **搜索性能**：关键词过滤在主线程对全量交易执行；标签映射预构建为 O(1) 查表，数据量在个人记账场景（万条级）无压力。
