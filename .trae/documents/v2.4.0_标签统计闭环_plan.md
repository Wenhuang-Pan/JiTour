## Implementation Steps

1. **版本号**：`pubspec.yaml` → `2.4.0+7`；`UpdateService.currentVersion` → `2.4.0`。
2. **Service 聚合**（stats_service.dart）：
   - 新增显式类 `TagStatEntry { final String tagId; final double amount; final int count; }`（禁止 dynamic，纯内存 DTO 不入 Hive，同文件定义）。
   - `static List<TagStatEntry> calculateTagStats(List<Transaction> transactions, bool isIncome)`：
     - 先按 `t.isIncome == isIncome` 过滤；
     - 遍历每笔的 `tagIds` 聚合金额与笔数；**跳过 `TagService.getTagById(id) == null` 的物理缺失 ID**（不进分子也不进分母）；
     - 结果按金额倒序；
     - 标注复杂度 `// O(n·k + m log m)`（n 交易数、k 平均标签数、m 标签数）。
   - 依赖方向：StatsService → TagService（同层，无循环依赖：TagService 不依赖 StatsService）。
3. **删除死代码**：移除 `TagService.getTagStatistics()`。
4. **重构标签统计卡片**（stats_screen.dart `_buildTagStats`）：
   - 拆为支出标签分区（`expenseTagStats` 非空时）与收入标签分区（`incomeTagStats` 非空时），分别使用 error/success 语义色标题，与"支出分类/收入分类"结构对齐；
   - 每分区**全量展示**标签（不截断），行样式沿用现有标签行（图标底、进度条、金额、占比），占比分母为该分区标签关联金额合计；
   - 每行包 `InkWell` + 尾部 `chevron_right_rounded`，点击调用 `_showTagDetail`；
   - 软删除标签（`tag.isActive == false`）正常显示但文字置灰并附"已停用"小标，保证历史金额可追溯；
   - 分区副标题注明"按标签归集，一笔账单可计入多个标签"；
   - 两分区都为空时返回 `SizedBox.shrink()`（保持现有行为）。
5. **标签明细下钻** `_showTagDetail(context, tagId, isIncome, periodTransactions)`：
   - 筛选 `t.tagIds.contains(tagId) && t.isIncome == isIncome` 的当期交易，日期倒序；
   - 复用 `_showCategoryDetail` 的 DraggableScrollableSheet 视觉（拖条、标签名标题、"N 笔 · 合计 ¥X"、流水行），金额颜色按收支；
   - 头部标签行显示标签图标与颜色；软删除标签标题后加"已停用"。
   - 为减少重复，将分类/标签明细中的流水行抽取为 `_buildTransactionDetailRow(t)` 私有方法，两处共用（纯 UI 重构，不改分类下钻行为）。
6. **校验**：改动文件 `dart analyze` 0 error；全量 `flutter analyze` 无新增告警。
7. **真机/模拟器验证清单**（系统 PowerShell）：
   - 支出/收入标签分区正确分离；同一标签只出现在对应分区；
   - 点击标签行弹出明细，笔数/合计正确，多标签账单在每个标签下都能查到；
   - 软删除标签置灰显示"已停用"且可下钻；物理删除标签的旧账单不导致占比失真；
   - 月/年视图切换、标签超过 6 个时全部显示；
   - 无标签账单的周期不显示标签分区。
8. **发布物**（用户确认发布后）：Obsidian v2.4.0 开发日志、release APK、GitHub Release（沿用 aapt2 校验 + 远端资产 SHA256 回算比对）。

## Dependencies and Considerations

- 无 Hive 模型/TypeId/字段变更，**零数据迁移**。
- 一笔多标签导致的金额重复累计是标签维度统计的固有口径（与分类维度互斥归属不同），通过副标题向用户明示，不做去重。
- 物理删除标签的旧交易仍保留标签 ID 字符串但无法解析，按"未知标签"排除出统计（避免出现不可识别行），其金额在账户/分类维度仍完整可见，不丢账。
- 标签数量级为十余个，全量展示无需折叠；未来若用户自建标签过百，再引入"展开全部"。
- `_showCategoryDetail` 行为在抽取共用行组件后必须逐行核对保持不变。

## Risks

- **软删除标签展示引起困惑**：以置灰 + "已停用"明示，且可下钻核对历史，优于金额凭空消失。
- **抽取明细行组件引入回归**：抽取后分类下钻与标签下钻共用，analyze 无 error 后真机重点回归分类明细点击。
- **占比口径误解**：副标题注明多标签归集规则；合计金额不与 KPI 收支总额直接比较。
