# 暗色模式数字颜色优化 + 分类手动拖动排序

## Context

用户提出两个优化点：

1. **暗色模式数字不可见**：夜间模式功能本身已存在（`settings_screen.dart` L74-156 可切换亮色/暗色/跟随系统，`main.dart` L81-88 已配置 `darkTheme`），但记账页支出金额硬编码为 `AppTheme.neutral900`（近黑色 #171717），暗色背景下完全看不见。审计发现全项目还有约 8 处同类硬编码深色文字（¥ 前缀、金额预览等）。**用户决策：全部修复**。
2. **分类无法自定义顺序**：支出/收入分类目前按 `createdAt` 排序，用户希望能手动拖动调整顺序。**用户决策：长按整卡拖动**（ReorderableListView 默认交互，不加拖动手柄）。

预期结果：暗色模式下所有数字/金额清晰可见；分类管理页可长按拖动排序，顺序全局生效（记账页分类网格、原生悬浮窗 chips、自动记账推送）且重启后保持。

## 功能二：分类手动拖动排序

### 1. 模型：`lib/models/category.dart`
- 新增字段：`@HiveField(7, defaultValue: 0) int sortOrder;`（`defaultValue` 使旧数据读取时自动补 0，hive_generator 2.0.1 支持，无需手写兼容代码）
- 构造器加 `this.sortOrder = 0`；`copyWith`、`toMap`、`fromMap` 同步补充

### 2. 重新生成适配器
```powershell
flutter pub run build_runner build --delete-conflicting-outputs
```
生成后 `category.g.dart` 的 read 为 `fields[7] == null ? 0 : fields[7] as int`，旧数据无缝兼容。

### 3. 服务：`lib/services/category_service.dart`
- **排序**：`getIncomeCategories()` / `getExpenseCategories()` 改为按 `sortOrder` 升序，`sortOrder` 相同回退 `createdAt`（保证迁移前显示稳定）
- **迁移**：`init()` 非首次分支（`migrateCategories()` 之后）追加 sortOrder 初始化——收入/支出分别检测：该类型非删除分类 **全部** `sortOrder == 0` 且数量 > 1 时，按 `createdAt` 顺序赋 0..n-1（升级用户触发一次；用户排序后出现非零值即不再触发；新装用户默认分类已带递增值不触发）
- **默认分类**：`_createDefaultCategories()` 循环中按索引赋 `sortOrder`
- **新增方法** `reorderCategories(bool isIncome, int oldIndex, int newIndex)`：`// O(n)` 取出排序列表 → 标准 remove/insert（`newIndex > oldIndex` 时 `newIndex -= 1`）→ 全量重写 `sortOrder = index` 并 `put` → `_syncCategoriesToNative()`（原生悬浮窗分类顺序同步更新，遵循"分类变更必推原生"规则）
- **`addCategory()`**：`sortOrder` 赋为同类型当前最大值 + 1（新分类排末尾；导入逐条添加自然保持导入顺序）
- **`restoreCategory()`**：恢复时 `sortOrder` 赋最大值 + 1 排到末尾，避免与现有值冲突

### 4. UI：`lib/screens/category_management_screen.dart`
- `_CategoryList` 的 `ListView.builder` → `ReorderableListView.builder`：
  - 每个 item 加 `key: ValueKey(category.id)`
  - `onReorder: (oldIndex, newIndex) => CategoryService.reorderCategories(isIncome, oldIndex, newIndex)`
  - 保持默认 `buildDefaultDragHandles: true`（Android 长按整卡拖动）
- `_CategoryCard` 无需改动；`ValueListenableBuilder` 监听 box 变更后自动重建为新顺序

### 5. 影响面（无需改代码，行为符合预期）
- `add_transaction_screen.dart` L133-139：默认选中排序后第一个分类
- `auto_accounting_provider.dart` L145-149：推送原生的分类名顺序跟随用户排序

### 6. 测试：`test/category_service_test.dart`
新增 `group('reorderCategories')`：
- 拖动后列表顺序正确且 `sortOrder` 已持久化
- 收入/支出排序互不影响
- `addCategory` 自动排到末尾
- 排序迁移：手动 put 全 0 数据后触发 `init()`，验证按 `createdAt` 分配递增值
