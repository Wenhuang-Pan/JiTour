# 记途 - 个人记账应用项目规则

## 技术栈约束
- 框架：`Flutter 3.41.x + Dart 3.11.x`，禁止使用 `dynamic`，泛型必须显式声明。
- 状态管理：`Provider 6.x`，所有状态必须通过 `ChangeNotifier` 管理，禁止全局变量。
- 数据库：`Hive 2.x`，所有实体必须实现 `TypeAdapter`，通过 `build_runner` 生成适配器。
- 图表：`fl_chart 0.66.x`，图表数据必须预先计算，禁止在 build 方法中处理。
- 国际化：`intl 0.20.x`，日期格式化必须使用 `DateFormat`，支持多语言。
- 工具库：`uuid 4.x` 生成唯一ID，`path_provider` 获取文件路径。

## 项目结构规范
- 新增页面必须放在 `lib/screens/`，文件名用 `snake_case`（如 `add_transaction_screen.dart`）。
- 新增服务必须放在 `lib/services/`，文件名用 `snake_case`（如 `category_service.dart`）。
- 新增模型必须放在 `lib/models/`，每个模型需配套生成 `.g.dart` 适配器文件。
- Provider 状态管理必须放在 `lib/providers/`，文件名用 `snake_case`（如 `theme_provider.dart`）。
- 自定义组件必须放在 `lib/widgets/`，文件名用 `snake_case`（如 `numpad.dart`）。
- 工具函数必须放在 `lib/utils/`，文件名用 `snake_case`（如 `uuid_util.dart`）。

## 代码质量硬约束
- 所有 `public` 方法必须包含 Dartdoc 注释，明确标注 `@param`、`@return`、`@throws`。
- UUID 生成必须使用全局 `UuidUtil.generate()` 方法，禁止直接调用 `_uuid.v4()`。
- 数值计算使用 `double`（金融场景需注意精度，后续可考虑 `decimal` 库）。
- Hive box 必须通过 `DatabaseService` 统一管理，禁止直接调用 `Hive.box()`。
- Hive adapter 注册前必须检查 `isAdapterRegistered()`，防止重复注册崩溃。
- `ColorScheme` 必须使用 `ColorScheme(...)` 构造器，禁止使用 `ColorScheme.fromSeed()`。
- Alpha 值必须使用 `0.0-1.0` 范围的 `double`，禁止使用 `0-255` 整数。

## UI/UX 规范
- 主题配置统一在 `lib/theme/app_theme.dart`，禁止在组件中硬编码颜色值。
- 主题颜色必须通过 `AppTheme.getPrimaryColor(context)` 动态获取，支持实时切换。
- 间距系统使用 `AppTheme.spaceXSmall/spaceSmall/spaceMedium/spaceLarge/spaceXLarge/spaceXXLarge/spaceXXXLarge`。
- 圆角系统使用 `AppTheme.radiusXS/radiusSmall/radiusMedium/radiusLarge/radiusXLarge/radiusXXLarge/radiusFull`。
- 文字样式使用 `Theme.of(context).textTheme`，禁止硬编码字体大小和颜色。
- 阴影效果使用 `AppTheme.cardShadow/cardShadowStrong/glowShadow()`，禁止自定义阴影。
- 动画时长使用 `AppTheme.animFast/animNormal/animSlow/animSlower`。

## 数据库操作规范
- 所有 Hive box 必须在 `DatabaseService.init()` 中统一打开和管理。
- 数据操作必须通过对应的 Service 类（如 `CategoryService`、`AccountService`），禁止在 UI 层直接操作 box。
- 查询结果必须排序后使用（如按日期倒序），禁止无序展示数据。
- 删除操作必须二次确认，禁止直接删除。

## 安全与质量红线
- 所有代码必须通过 `flutter analyze` 校验，禁止提交有错误的代码。
- 禁止硬编码敏感信息（如 API 密钥、密码），必须使用配置文件或环境变量。
- 用户输入必须校验（如金额格式、日期范围），禁止直接使用未校验数据。
- 循环内禁止重复创建对象，高频函数需标注时间复杂度（如 `// O(n log n)`）。
- 异常捕获后必须给出友好提示（如 `ScaffoldMessenger` 显示 SnackBar），禁止静默失败。

## 工程化习惯
- 优先使用构造器注入，禁止字段注入。
- 日志必须使用 `debugPrint`，禁止 `print`。
- 捕获异常后必须记录日志并给出用户提示，禁止仅打印日志。
- 新增功能必须同步更新开发文档，记录功能特性和修改内容。
- 代码提交前必须运行 `flutter analyze`，确保无错误。
- 版本号格式：`{major}.{minor}.{patch}+{build}`（如 `1.2.0+2`）。

## 版本文档规范
- 每个版本必须在 Obsidian 中输出开发文档，便于把控开发进度。
- 文档路径：`F:\AI Notebook\Obsidian\Learning Notebook\AI 开发笔记\记途 - 个人记账应用开发笔记\`。
- 文档命名：`v{version} - {description}.md`（如 `v2.0.0 - 开发日志.md`）。
- 文档内容必须包含：
  - 版本概述（版本号、发布日期、开发周期）
  - 新增功能（功能描述、实现要点、测试情况）
  - 修改内容（代码优化、Bug 修复、UI 调整）
  - 文件变更汇总（新增文件、修改文件、删除文件）
  - 待办事项（下一版本计划、已知问题）
  - 测试结果（功能测试、性能测试、兼容性测试）

## Git 规范
- 分支命名：`v{version}-{type}`（如 `v2.0.0-dev`、`v2.0.0-release`）。
- 提交信息：`{version}: {description}`（如 `v2.0.0-dev: 代码质量优化与Bug修复`）。
- `.gitignore` 必须包含 `.dart_tool/`、`.pub-cache/`、`build/`、`*.hive`、`*.lock`。

## 简约风格设计规范
- 配色：主色调为紫色系（#6366F1），中性色阶为柔和灰色。
- 阴影：细腻柔和，减少视觉噪音，卡片默认无阴影。
- 圆角：适度圆润（12-16px），不夸张。
- 留白：大量留白，提升呼吸感，间距使用 `spaceXLarge/spaceXXLarge`。
- 排版：字重使用 `w400/w500/w600/w700`，行高使用 `1.3-1.5`。
- 动效：简洁流畅，避免过度动画。
